# Fase 0 Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verificar, con RustDesk OSS dockerizado, si el `hbbs` OSS expone lo mínimo que el control-plane necesita (estado de peers online + provisioning de agentes), o si el enfoque "wrap" no es viable sin RustDesk Pro.

**Architecture:** Levantar RustDesk server (hbbs+hbbr) vía Docker compose. Registrar un agente RustDesk de prueba. Inspeccionar el estado que persiste hbbs (hipótesis: sqlite `db_v2.sqlite3`). Escribir un adapter Python mínimo que lea ese estado y liste peers con su status online. El entregable es una **decisión GO/NO-GO documentada** + docker-compose reusable + adapter de lectura verificado (o el fallo documentado).

**Tech Stack:** Docker + docker-compose, RustDesk OSS (`rustdesk/rustdesk-server`), Python 3.12, pytest, sqlite3 (stdlib).

## Global Constraints

- No se modifica el código de RustDesk. Se corre la imagen oficial `rustdesk/rustdesk-server` sin patchear.
- Python 3.12+, hexagonal: el adapter de lectura implementa un port (Protocol), no se acopla el use-case a sqlite.
- Tests EN repo + gate (política sme-cyber post PR#18).
- Toda lectura de estado de hbbs vive SOLO en `adapters/rustdesk_state`.
- Criterio de salida del spike: decisión GO/NO-GO escrita en `docs/superpowers/specs/FASE0-FINDINGS.md` antes de planificar el MVP.

- [ ] **Step 1: Escribir docker-compose**

```yaml
# infra/docker-compose.yml
services:
  hbbs:
    image: rustdesk/rustdesk-server:latest
    command: hbbs -r hbbr:21117
    ports:
      - "21114:21114/tcp"   # web console OSS (limitado)
      - "21115:21115/tcp"
      - "21116:21116/tcp"
      - "21116:21116/udp"   # rendezvous
      - "21118:21118/tcp"
    volumes:
      - ./data:/root
    depends_on: [hbbr]
    restart: unless-stopped
  hbbr:
    image: rustdesk/rustdesk-server:latest
    command: hbbr
    ports:
      - "21117:21117/tcp"   # relay
      - "21119:21119/tcp"
    volumes:
      - ./data:/root
    restart: unless-stopped
```

# control-plane/src/domain/device.py
from dataclasses import dataclass
from datetime import datetime

@dataclass(frozen=True)
class Device:
    id: str
    alias: str | None
    last_online: datetime | None

    def is_online(self, now: datetime, threshold_s: int = 60) -> bool:
        if self.last_online is None:
            return False
        return (now - self.last_online).total_seconds() < threshold_s
```

# control-plane/src/adapters/rustdesk_state.py
import sqlite3
from datetime import datetime
from src.domain.device import Device

class HbbsSqliteStateReader:
    """Lee estado de peers desde el sqlite de hbbs. Ajustar query a schema real."""

    def __init__(self, db_path: str) -> None:
        self._db_path = db_path

    def list_devices(self) -> list[Device]:
        con = sqlite3.connect(self._db_path)
        try:
            rows = con.execute("SELECT id, last_online FROM peer").fetchall()
        finally:
            con.close()
        return [
            Device(
                id=row[0],
                alias=None,
                last_online=datetime.fromtimestamp(row[1]) if row[1] else None,
            )
            for row in rows
        ]
```
